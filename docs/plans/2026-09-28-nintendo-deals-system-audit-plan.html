Fix trust before adding more sources.

The stack is already small enough. The problem is not missing infrastructure; it is incomplete catalog traversal, stale source semantics, whole-document state writes, and too little boundary testing.

Recommended architecture: Vercel for the site and inbound Telegram webhook, GitHub Actions for scheduled source work and outbound messages, conditional Blob writes where concurrency matters, and immutable versioned Blob snapshots for large read-mostly enrichment maps.

Priority findings

Ranked by user-visible correctness and risk of losing state, not by ease of implementation.

P0 · completeness

The worker silently drops 2,145 offers

Alerts, digest selection, and rating discovery all run on an unspecified first page. Full pagination plus direct watched-game lookup is the first fix.

P0 · source drift

Nintendo Life ingestion is broken and semantically stale

The parser expects the old wrapper and consumes duplicate all-time guide URLs, not current eShop Selects.

P1 · state

Preference writes can race

Website and Telegram actions read and overwrite one JSON document. Use Blob's documented ifMatch conditional write with a bounded retry instead of adding another database.

P1 · feedback

Telegram claims success too early

The callback is answered with success before persistence. Retried updates have no completed-update record.

P1 · UX

Deep links fail at runtime

Next.js 16 requires the homepage query object to be awaited. Desktop and mobile both render the list instead of the selected modal.

P2 · operability

The scheduler can miss a day quietly

Top-of-hour runs may be delayed, while the workflow refuses to run after its 20-minute gate.

Target architecture

A deeper rewrite would add more moving parts without fixing the trust boundaries. This keeps the current runtime and storage split, adding optimistic concurrency only where state changes.

Implementation sequence

Each phase has a hard acceptance gate. Do not start a storage migration while catalog correctness and callback behavior are still ambiguous.

Correctness at existing boundaries
  1. Paginate Nintendo to numFound and fetch watched identifiers directly.
  2. Post-filter on the actual discounted price.
  3. Honor search offsets and prove pages are disjoint.
  4. Await the homepage query object and cover login-preserved deep links.
  5. Persist Telegram actions before success feedback and use date-scoped delivery keys for retry-safe sends.
Gate: full count equals source count; the known deep link opens; 17.49-EUR cards are absent; a failed callback never claims success.
Source semantics and freshness
  1. Use eShop Selects with sanitized parser fixtures.
  2. Keep Current Offers as comparison only.
  3. Refresh missing and under-two-month IGDB entries with platform evidence; retain older successful matches.
  4. Use Steam's documented review summary and retain SteamSpy only as failure-tolerant cached tags.
  5. Separate Nintendo Life and NT Deals snapshots with provenance timestamps.
Gate: source drift fails closed; both signals can coexist; only missing and new-release ratings enter a bounded queue; SteamSpy failure preserves known tags.
State integrity and security
  1. Use ETag-guarded conditional Blob writes and bounded retry for preferences and Telegram replay state.
  2. Migrate 157 hidden, 10 watched, and 4 thinking entries with a reversible manifest.
  3. Replace raw-password session state with an opaque signed session.
  4. Distinguish provider failure from an empty valid snapshot.
  5. Validate bulk snapshot shapes and make maintenance scripts dry-run by default with explicit --apply.
  6. Redact credential-bearing destinations from errors.
Gate: concurrent actions preserve both changes; migration counts match; no failed read can erase a valid snapshot.
Scheduling, accessibility, and operations
  1. Use one timezone-aware 10:07 Europe/Madrid schedule.
  2. Publish a redacted run artifact with counts, durations, and failure stage.
  3. Add dialog semantics, focus containment, labelled controls, and focus restoration.
  4. Apply one original-Switch catalog contract that explicitly excludes Switch 2 in every query path.
  5. Pin workflow actions and script dependencies, parity-test content policy, and add the AIUP documentation checker.
Gate: one visible run per Madrid day; responsive and accessibility checks pass; release evidence identifies preview versus production.

Approval boundary

Plan approval authorizes implementation and local deterministic testing only. It does not authorize a production scraper run, preference migration, Telegram message send, webhook reconfiguration, git push, or production Vercel promotion.

Defaults included in the plan: only original Switch offers remain in scope; the daily run moves to 10:07 Madrid; NT Deals remains a secondary Deal Pick from its Spanish Switch feed; SteamSpy remains optional cached tag enrichment; preferences stay in Blob and gain conditional writes rather than a second database.
